# Практика 13. printf() і функції дати

**Варіант 5 — Автосалон.** Таблиці: `cars` (вимір 1), `clients` (вимір 2), `sales` (фактова). Працюю з тим самим файлом `.db`, що й у Практиках 4-12.

## Завдання 1. printf() для числової колонки

```sql
SELECT id, price AS raw_price, printf('%.2f грн', price) AS formatted_price
FROM sales;
```

Числова колонка фактової таблиці — `sales.price`. Сире значення виглядає як `650000.0`: це тип `REAL`, без одиниці виміру, а кількість знаків залежить від самого числа. Після `printf('%.2f грн', price)` виходить `650000.00 грн`: завжди два знаки після крапки та вказана валюта. Для читача звіту різниця в тому, що з першого погляду зрозуміло, що це сума в гривнях, а рядки виглядають однаково. Результат `printf()` має тип `TEXT`, тому для обчислень його використовувати не можна.

## Завдання 2. printf() з вирівнюванням

```sql
SELECT id, printf('%05d', id) AS id_padded, printf('%12.2f', price) AS price_aligned
FROM sales;
```

`%12.2f` виділяє мінімум 12 символів під число, коротші значення доповнюються пробілами зліва, тому цифри вирівнюються за правим краєм: `   650000.00`. `%05d` доповнює ціле нулями до п'яти цифр (`00001`).

Навіщо це, якщо результат і так показується в таблиці: клітинки таблиці в DB Browser вирівнюють текст за лівим краєм, тож без ширини розряди різних сум не стоять одна під одною. Коли вивід копіюють у текстовий звіт, консоль чи `.md`, вирівняні за шириною значення зберігають рівні стовпці. Нулі зліва дають ідентифікаторам однакову довжину. Мінус: результат — текст, тому вирівняні значення не можна сортувати як числа.

## Завдання 3. Зсув дати

```sql
SELECT id, sale_date, date(sale_date, '+14 days') AS return_deadline
FROM sales;
```

Для кожного продажу обчислено дату `sale_date + 14 днів`, наприклад `2026-02-18` → `2026-03-04` (SQLite сам враховує кінець місяця). Практичний сенс у моєму варіанті: це остання дата, до якої клієнт може повернути або обміняти автомобіль без штрафу. Так само можна рахувати кінець гарантії (`'+1 year'`).

## Завдання 4. strftime() і GROUP BY за місяцем

```sql
SELECT strftime('%Y-%m', sale_date) AS ym, COUNT(*) AS sales_count
FROM sales
GROUP BY ym
ORDER BY ym;
```

| ym | sales_count |
|---|---|
| 2026-02 | 2 |
| 2026-03 | 2 |
| 2026-04 | 2 |
| 2026-05 | 2 |
| 2026-06 | 2 |

Групування за місяцем вибране тому, що всі 10 продажів припадають на 2026 рік, і група за роком дала б один рядок (`2026 | 10`), який нічого не показує. Групувати довелося за результатом `strftime()`, а не за `sale_date`, бо `sale_date` містить повну дату, і майже кожен продаж мав би власну групу з `COUNT(*) = 1`. `strftime('%Y-%m', ...)` перетворює різні дати одного місяця на однакове значення, і саме за ним їх можна об'єднати.

## Завдання 5. Свідома помилка з некоректною датою

```sql
SELECT strftime('%Y', 'not-a-date');             -- NULL
SELECT date('not-a-date');                       -- NULL
SELECT strftime('%Y', payment_method) FROM sales; -- NULL у кожному рядку
```

SQLite **не повернула помилку**, а повернула `NULL` (`typeof` = `null`). Те саме відбулося для колонки `payment_method`, яка дат не містить. На це не можна покладатися як на автоматичну перевірку дат: некоректне значення мовчки перетворюється на `NULL`, запит виконується успішно, і далі `NULL` тихо потрапляє у групування та агрегати (наприклад, окрема група `NULL` у `GROUP BY` або пропущені рядки). Помилку ніхто не побачить.

## Відповіді на контрольні питання

**1. Чим printf() відрізняється від зміни значення в таблиці?** `printf()` лише формує текстовий результат у `SELECT`. Збережене значення колонки не змінюється: запит нічого не записує, і `SELECT price FROM sales` після цього повертає `650000.0`, як і раніше. Змінити значення в таблиці можна тільки через `UPDATE`.

**2. Чому strftime('%Y', ...) повертає текст і коли це важливо?** `strftime()` завжди повертає рядок. Це видно з перевірки: `typeof(strftime('%Y', sale_date))` дає `text`, а `strftime('%Y', sale_date) = 2026` повертає `0`, бо текст `'2026'` не дорівнює числу `2026`. Тому для порівняння з числом треба писати `CAST(strftime('%Y', sale_date) AS INTEGER) = 2026` (дає `1`). Для сортування різниця теж важлива: рядки сортуються посимвольно, і без однакової довжини (наприклад, `'9'` проти `'10'`) порядок буде неправильним. Рік і місяць у форматі `'%Y-%m'` сортуються коректно саме тому, що вони однакової довжини.

**3. Що висновок Завдання 5 означає для CHECK-обмежень на дати?** Некоректна дата дає `NULL`, а CHECK пропускає рядок, якщо вираз повертає `NULL` (а не лише `TRUE`). Тому `CHECK (date(sale_date) > '2000-01-01')` не відсіче `'not-a-date'`. Потрібно явно перевіряти `NULL`: `CHECK (date(sale_date) IS NOT NULL)`, а ще краще `CHECK (date(sale_date) = sale_date)`, що вимагає саме формату `YYYY-MM-DD`.
