# Практика 18. Згенеровані стовпці

**Варіант 5 — Автосалон.** Два віртуальні стовпці додано до таблиці `cars` у базі після практики 15. Жодну наявну таблицю не видалено.

## Завдання 1. Ціна з ПДВ

```sql
ALTER TABLE cars ADD COLUMN price_with_vat REAL
    GENERATED ALWAYS AS (ROUND(price * 1.2, 2)) VIRTUAL;
```

`price` у прайсі салону — сума без ПДВ. Похідна колонка показує ціну для покупця: ті самі гроші плюс 20% ПДВ. Формула бере лише колонки цього рядка.

| id | brand | price | price_with_vat | status | is_sold |
|---|---|---:|---:|---|---:|
| 1 | Toyota | 720000.0 | 864000.0 | в наявності | 0 |
| 2 | Volkswagen | 650000.0 | 780000.0 | продано | 1 |
| 3 | Skoda | 780000.0 | 936000.0 | продано | 1 |
| 4 | Renault | 580000.0 | 696000.0 | в наявності | 0 |
| 5 | Hyundai | 950000.0 | 1140000.0 | зарезервовано | 0 |
| 6 | Ford | 490000.0 | 588000.0 | продано | 1 |

Для Toyota Corolla 720000 × 1.2 = 864000. Для Hyundai Tucson 950000 × 1.2 = 1140000.

## Завдання 2. Прапорець проданого авто

```sql
ALTER TABLE cars ADD COLUMN is_sold INTEGER
    GENERATED ALWAYS AS (status = 'продано') VIRTUAL;
```

Порівняння дає 1, коли статус саме `продано`, і 0 для `в наявності` та `зарезервовано`. У вибірці вище це збігається зі статусом кожного рядка: продані Golf і Focus мають 1, решта 0. Якби `status` був `NULL`, прапорець теж став би `NULL`, бо порівняння з `NULL` не є ні істиною, ні хибністю. У цій таблиці статус оголошено як `NOT NULL`, тому такого рядка зараз немає.

## Завдання 4. Автоматичний перерахунок

До зміни Toyota Corolla (`id = 1`) мала ціну 720000.0 і ціну з ПДВ 864000.0. Команда змінює базову колонку, не згенеровану:

```sql
UPDATE cars SET price = 800000 WHERE id = 1;
```

Після неї ціна 800000.0, а `price_with_vat` сам став 960000.0, тобто 800000 × 1.2. Окремої команди для похідної колонки не було.

## Завдання 5. Фільтр за похідною ціною

```sql
SELECT id, brand, price_with_vat
FROM cars
WHERE price_with_vat > 900000
ORDER BY id;
```

| id | brand | price_with_vat |
|---|---|---:|
| 1 | Toyota | 960000.0 |
| 3 | Skoda | 936000.0 |
| 5 | Hyundai | 1140000.0 |

Умова називає те, що потрібно менеджеру: ціна з ПДВ понад 900000. Повторювати `ROUND(price * 1.2, 2) > 900000` у кожному запиті легше розійтися з формулою колонки. Одна назва тримає правило в одному місці.

## Відповіді на контрольні питання

**1. Чому тут можна додати лише VIRTUAL, а не STORED?** Спроба `ALTER TABLE ... STORED` завершилася текстом `cannot add a STORED column`. Таблиця `cars` уже існує і вже містить рядки. `STORED` мав би записати обчислене значення в кожен наявний запис, а `ADD COLUMN` так таблицю не переписує. `VIRTUAL` нічого не зберігає і рахується під час читання, тому його можна додати до готової таблиці.

**2. Що буде, якщо видалити базову колонку?** `price_with_vat` залежить від `price`, а `is_sold` від `status`. `ALTER TABLE cars DROP COLUMN price` SQLite відхилить, доки існує згенерований стовпець, який цю колонку використовує. Спочатку треба прибрати похідний стовпець.

**3. Чому заборона прямого UPDATE — перевага?** Помилка завдання 3: `cannot UPDATE generated column "price_with_vat"`. У колонку не можна підставити довільне число, яке розходиться з формулою. Ціна з ПДВ завжди дорівнює ціні без ПДВ, помноженій на 1.2, інакше прайс і звіт показували б різні суми.
