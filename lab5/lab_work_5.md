# Практика 5. Обмеження цілісності: NOT NULL, UNIQUE, CHECK, DEFAULT

**Варіант 5 — Автосалон.** Продовження Практики 4. Усі чотири обмеження додано до двох уже наявних таблиць-вимірів — `cars` і `clients` — перестворенням таблиці (`RENAME` → `CREATE` з новим обмеженням → `INSERT ... SELECT` → `DROP`), оскільки SQLite не підтримує `ALTER TABLE ... ADD CONSTRAINT`. На час кожного перестворення використано `PRAGMA legacy_alter_table = ON`, щоб `RENAME` не переписував текст `FOREIGN KEY` у `sales`, яка посилається на `cars` і `clients`.

## Завдання 1. NOT NULL — `cars.price`

Ціна — обов'язкова характеристика позиції каталогу.

Перевірка — вставка без `price`:
```
Error: NOT NULL constraint failed: cars.price
```

## Завдання 2. UNIQUE — `clients.phone`

Номер телефону однозначно ідентифікує клієнта.

Перевірка — вставка з номером, що вже є (`+380671234567`, клієнт Коваленко):
```
Error: UNIQUE constraint failed: clients.phone
```

## Завдання 3. CHECK — `cars.price > 0`

Ціна — грошова величина, від'ємною чи нульовою бути не може.

Перевірка А — від'ємна ціна:
```
Error: CHECK constraint failed: price > 0
```

Перевірка Б — додатна ціна (`550000`): виконано без помилок, рядок додано.

## Завдання 4. DEFAULT — `clients.city`

Автосалон розташований у Києві, і більшість клієнтів, для яких місто не вказали окремо, реалістично саме звідти — тому додано `DEFAULT 'Київ'`.

Підтверджене значення: вставлено клієнта без `city`; `SELECT` показав, що підставилося саме `'Київ'`:
```sql
INSERT INTO clients (last_name, first_name, phone) VALUES ('Гриценко', 'Олена', '+380507654321');
SELECT id, last_name, first_name, city FROM clients ORDER BY id DESC LIMIT 1;
-- 7|Гриценко|Олена|Київ
```

## Завдання 5. Порушення через UPDATE

Обмеження `CHECK (price > 0)` із Завдання 3 порушено оновленням наявного рядка (`id = 1`, Toyota Corolla, `720000`):

```sql
UPDATE cars SET price = -100000 WHERE id = 1;
```

```
Error: CHECK constraint failed: price > 0
```

Рядок лишився незмінним (`price = 720000.0`) — обмеження `CHECK` діє однаково при `INSERT` і при `UPDATE`.

## Завдання 6. Обґрунтування обмежень

- **NOT NULL (`cars.price`).** Автомобіль у каталозі без ціни — незавершений, безглуздий запис: продаж без ціни неможливий за визначенням.
- **UNIQUE (`clients.phone`).** Телефон — природний спосіб відрізнити клієнтів один від одного; дублікат номера в різних рядках означав би або помилку введення, або того самого клієнта, записаного двічі.
- **CHECK (`cars.price > 0`).** Ціна — фізична грошова величина, від'ємне чи нульове значення завжди є помилкою введення, а не легітимним бізнес-випадком.
- **DEFAULT (`clients.city`).** Автосалон фізично розташований в одному місті (Києві), тож якщо оператор не вказав місто клієнта, найбільш імовірне значення — саме воно, а не порожнє поле.

## Підсумкова перевірка

```sql
PRAGMA foreign_key_check;
-- порожньо — порушень немає

SELECT COUNT(*) FROM cars;    -- 7  (6 вихідних + 1 з Завдання 3)
SELECT COUNT(*) FROM clients; -- 7  (6 вихідних + 1 з Завдання 4)
SELECT COUNT(*) FROM sales;   -- 10 (без змін)
```
